# Part 0 — Confidence-Learning Evaluation (trust vector vs alternatives)

Question: does Sam's Beta trust-vector design, **as built** in
`apps/ios/Platform/Persistence/Services/ConfidenceLearningService.swift`
(alpha @ `2e77938`), hold up against independent correctness labels — and
where do alternatives beat it?

Everything here is offline. No live LLM/API calls exist in this evaluation.

## Layout

| Path | What it is |
| --- | --- |
| `confidence_port.py` | Line-cited Python port of the Swift service (priors, assessSignal, assess, recordOutcome, calibrationSnapshots). Differentially checked against hand-computed fixtures in `tests/test_port_fixtures.py`. |
| `replay_runner.py` | Projects PR #7's reverse-meal states into the exact four signals (vision 0.32 / recipe 0.30 / coverage 0.23 / margin 0.15), replays the 12 episodes through the port under a chosen reward channel (`proxy` or `truth`), and replays PR #53's changed-family correction histories for the drift question. |
| `metrics.py` | ECE (15-bin, bin edges reported), Brier, reliability curve, decision-quality counts, trailing-window stabilization, first-exact timing. |
| `calibrators.py` | Alternatives: isotonic (PAVA) and a small logistic calibrator (raw + per-key one-hots, L2), both with leave-one-episode-out evaluation. |
| `experiments/run_all.py` | Runs every arm, sweep, alternative, drift replay, and extended passes; writes `results/metrics.json` (byte-stable for fixed seed) and a determinism self-check. |
| `results/metrics.json` | All measured numbers with 95% bootstrap intervals (B=1000, seed 20261011). |
| `results/tables.md` | Rendered headline tables (generated by `experiments/tables.py`). |
| `data/` + `data/PROVENANCE.md` | Offline copies of PR #7 and PR #53 artifacts with upstream paths and re-verified SHA-256 hashes. |
| `FINDINGS.md` | Verdict: where the design wins, where it loses, named fixes, recommendation. |

## How to run

```bash
python3 -m pytest evaluation/preference-learning/confidence/tests/ -q
python3 evaluation/preference-learning/confidence/experiments/run_all.py
python3 evaluation/preference-learning/confidence/experiments/tables.py
```

Determinism: running `run_all.py` twice produces byte-identical
`results/metrics.json` (the script asserts this itself; the field
`determinism_selfcheck` records it).

## Method in one paragraph

The port replays PR #7's 12 reverse-meal episodes through the exact Swift
math. Two reward channels feed the same update path: `proxy` (what the
as-built app stores — the producer's self-assessed outcome) and `truth`
(independent correctness). Because `recordOutcome` blends
`0.55·outcome + 0.45·(1−|reward−adjustedScore|)` before storing, the two
arms measure what the trust vector learns when it can and cannot see the
truth. Mode decisions are judged against truth labels; calibration is
reported against truth for every arm; and the service's own
`calibrationSnapshots` error (against blended rewards) is reproduced to
quantify the telemetry gap. Alternatives (prior sweeps, decay sweeps,
isotonic, logistic) run on identical episodes with leave-one-episode-out
where fitting is involved. Drift uses PR #53's changed-family histories
(truth flip mid-history) plus two synthetic capability-drop transforms on
the reverse-meal substrate.

## What is NOT here

- No native Swift execution: the port is differentially checked against
  hand-computed fixtures transcribed from the Swift source; the optional
  Linux Swift build of the real service was not required for any number
  reported here. Anything that would need macOS/Xcode is labeled
  UNVERIFIED-NATIVE in FINDINGS.md and was not run.
- No merges, no workflow edits, no live API spend.
