# FLDomain JSON fixtures

Frozen cross-language contract files for the FLDomain domain types. The
Swift, TypeScript and Python sides of FridgeLuck all read and write these
shapes; a fixture is the single source of truth for what each type looks
like on the wire.

## The contract

1. **Schema version.** `manifest.json` carries the contract version, e.g.
   `"schema": "fldomain.v1"`. Consumers check it explicitly and refuse an
   unknown major version (see `FLSchema` in `Sources/FLDomain/FLJSON.swift`).
   Additive minor versions have the form `fldomain.v1.<n>`; a minor addition
   must remain readable by every v1 decoder.
2. **Canonical bytes.** Each fixture file is exactly what the Swift canonical
   encoder produces: `JSONEncoder` with `[.prettyPrinted, .sortedKeys]` and
   timestamps as ISO 8601 UTC strings with millisecond precision
   (`2026-10-11T12:00:00.000Z`). Decoders accept fractional seconds or none,
   so any ISO 8601 producer can be read; encoders always emit the canonical
   form.
3. **Unknown evidence stays unknown.** `QuantityEvidence.unknown` encodes as
   `{"kind": "unknown"}` and never becomes a number downstream.
4. **Round-trip equality.** Decoding a fixture and re-encoding it canonically
   must reproduce the file byte for byte.

## Verification

- Swift: `swift test --filter FixtureContractTests` (from
  `packages/FridgeLuckCore`) decodes every file and demands byte equality.
- Python: `python3 scripts/data/check_core_fixtures.py` checks the manifest,
  sorted keys at every level, canonical timestamp shape, and the unknown
  evidence form with the standard library only.

## Regenerating

The fixture files are generated by the Swift test to guarantee byte
fidelity — never edit them by hand:

    cd packages/FridgeLuckCore
    FL_UPDATE_FIXTURES=1 swift test --filter FixtureContractTests

Review the diff as a contract change: every byte in these files is the
interface the TypeScript backend and Python tooling also implement.
