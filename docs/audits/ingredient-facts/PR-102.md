## 2. Fail-open behavior found

1. **Design-arm proposals bypass the recheck entirely.** In this join the coach, planner and companion design arms generate and gate proposals through their own scripts (`proposalGating.ts`, `opening-batch.ts`, …). None of them calls `allergenViolations` — the recheck exists only behind `reads.swapViolations`, i.e. substitution reads. A coach proposal ("use the tamari instead of the soy sauce", "stir cream cheese into the sauce") is gated on budget, silence and policy — never on the eaters' restrictions. A wheat+soy avoider's coach suggests **tamari**; a milk avoider's planner suggests **cream cheese**; a vegetarian's companion reminds them about the **Worcestershire** in the pan — all pass.
2. **The underlying maps still fail open.** `allergens.ts` is byte-identical to the suite-D head: absence from the two maps returns `[]` violations (line 73), and no map encodes diet restrictions at all — `vegetarian`/`vegan` restrictions match nothing (lard, gelatin, meat all pass).
3. **The design world never tests restrictions.** `shared-world.ts:110` ships one eater, `restrictions: []`, so the design-arm equivalence/policy tests cannot observe a restriction violation even if the gating called the recheck. The suite proves gating determinism over an empty restriction set.
4. **No unknown state.** As in suite D: unknown ingredient ⇒ zero tokens ⇒ "no violations". The design arms have no representation for "this ingredient's composition is unknown — ask".

## 3. Exact changes needed (file by file)

Goal: one fail-closed evaluator for every proposal path — design arms included; unknown ⇒ ask the user; meal restrictions are the union of every eater's restrictions (`FLRestrictions.union`).

### 3.1 New module `backend/gemini-agent/src/lechef/ingredientFacts.ts`

Same module as specified for suite D (PR #101 fix list §3.1): load `data/ingredient-facts`, expose `unionRestrictions(eaters)` and `evaluate(ingredient, restrictions)` with `allowed | violated | unknown` verdicts; validate eater restriction strings against the `FLAllergen`/`FLDiet` vocabulary.

### 3.2 `backend/gemini-agent/src/lechef/allergens.ts`

Delete both maps; keep `allergenViolations`/`recheckSwapAllergens` as thin fail-closed wrappers (see the PR #101 fix list §3.2 for the exact before/after).

### 3.3 `backend/gemini-agent/src/lechef/designs/coach/scripts/proposalGating.ts`

Add the restriction gate to the proposal pipeline, before budget/silence ordering (an unsafe proposal is not merely deprioritized — it is refused):

```ts
// after
const verdict = evaluate(proposal.ingredient, unionRestrictions(world.eaters));
if (verdict.kind === "violated") return { ...gate, refused: "restriction", reason: verdict.reason };
if (verdict.kind === "unknown")  return { ...gate, refused: "unknown-facts", ask: true }; // ask the user
```

Every script that can surface an ingredient to the user (`proactiveReads.ts`, `world.ts`-derived proposals) passes through the same helper — no script keeps its own list.

### 3.4 `backend/gemini-agent/src/lechef/designs/planner/scripts/opening-batch.ts` (+ `shared-world.ts`, `remember-close.ts`)

- The opening batch and remembered notes reference pantry ingredients; run each through `evaluate` with the world's union restrictions before the batch is emitted.
- `shared-world.ts`: give the design world at least one eater with non-empty restrictions (e.g. `["milk"]`) or add a second eater, so the union path is exercised; keep a zero-restriction variant for the existing determinism tests.

### 3.5 `backend/gemini-agent/src/lechef/runtime.ts`

Keep `reads.swapViolations` but return the richer verdict (violated / unknown-with-missing-fields / allowed) so designs can distinguish refusal from ask-the-user.

### 3.6 Tests (`backend/gemini-agent/src/__tests__/lechef/designs/`)

- `coach/policy.test.ts`, `planner/policy.test.ts`: proposals naming restricted ingredients are refused with a restriction reason — tamari (wheat+soy eater), cream cheese (milk eater), lard/Worcestershire (vegetarian eater); unknown-composition ingredients produce the ask path, never a silent pass.
- `coach/equivalence.test.ts`, `planner/equivalence.test.ts`: worlds whose eaters carry restrictions must show the recheck firing in the equivalence arm, not only in runtime reads.
