## 2. Fail-open behavior found

1. **`permits` defaults fail open.** `Restriction.permits(canonicalName:allergens:dietTags:)` (FLDomain/Restriction.swift lines 110–119) takes the ingredient's allergens and diet tags with **default `[]` arguments**. Any caller that omits composition gets a name-only check (custom exclusions only): an ingredient is blocked only if the user hand-listed its exact canonical name. Cream cheese passes a milk household, tamari passes a wheat+soy household, lard and Worcestershire pass Ben's `vegetarian` — unless someone typed the name in.
2. **`SwapGate.recheck` trusts caller-declared composition.** The substitute's allergens are a bare `substituteAllergens: Set<Allergen>` parameter with no evidence requirement; passing `[]` — which is exactly what the join's own suite does at `FullWeekScenarioTests.swift:273–279` for the olive-oil swap — yields "rechecked against every eater: no allergen clash" for any ingredient whatever its real composition. A tamari substitute for a wheat+soy household passes identically when the caller declares nothing, and a variable-composition product (stock cube, bouillon) has no way to be flagged. The gate rechecks **allergens only**: Ben's `vegetarian` exclusion never screens a substitute at all, so lard or Worcestershire pass unconditionally.
3. **The join wires no facts anywhere.** `HouseholdWorld.pantryLines()`/`assistantLines()` carry canonical names and quantities; nothing in the kit attaches composition to recipes or pantry items, and the consumed capability flows do their own caller-claims-based screening (see the PR #103 fix list). The week's `ScenarioTrace` golden bytes therefore record the outcomes of the fail-open machinery — replaying them preserves fail-open behavior as if it were a contract.
4. **No unknown state.** `SwapGate.Verdict` is `allowed: Bool` plus an explanation; `permits` returns Bool. Neither can express "composition unknown — ask the user", so an unreviewed ingredient is indistinguishable from a verified-safe one everywhere in the join.

### 3.2 `packages/FridgeLuckCore/Sources/FLDomain/Restriction.swift` (the file this PR introduces)

This PR adds the shared type, so it should carry the fail-closed shape from the start — coordinate with the PR #103 fix list §3.2 (same file, same change; the join's manifest note already treats FLDomain needs as contract requests):

- **Remove the default arguments** from `permits(canonicalName:allergens:dietTags:)` (line 110) so no caller can silently claim "no allergens".
- Add the facts-based verdict alongside `union(_:)` (line 90), which is already correct:

```swift
import FLIngredientFacts

public enum RestrictionVerdict { case allowed; case violated(String); case unknown(String) }

extension Restriction {
  /// This person's restrictions in the shared facts vocabulary.
  public var flRestrictions: FLRestrictions { /* map Allergen→FLAllergen, DietExclusion→FLDiet, keep customExclusions */ }

  /// Facts-driven, three-valued: unknown means ask the user, never allowed.
  public func verdict(for canonicalName: String, store: FLIngredientFactsStore) -> RestrictionVerdict {
    switch store.evaluate(ingredient: canonicalName, restrictions: flRestrictions) {
    case .allowed:        return .allowed
    case .violated(let v): return .violated(v.reason)
    case .unknown(let u):  return .unknown("composition unknown — ask the user (\(u))")
    }
  }
}
```

### 3.3 `packages/ScenarioJoin/Sources/FLScenarioKit/HouseholdWorld.swift` — `SwapGate`

Composition comes from the store, not the caller; the union of every eater's restrictions is evaluated inside the gate:

```swift
// before — composition is whatever the caller asserts (suite passes [] by hand)
public static func recheck(
    substitute: IngredientReference,
    substituteAllergens: Set<Allergen>,
    eaterAllergens: [(name: String, allergens: Set<Allergen>)]
) -> Verdict { … }

// after — composition from the shared facts store; unknown ⇒ ask
public static func recheck(
    substitute: IngredientReference,
    eaters: [(name: String, restrictions: FLRestrictions)],
    store: FLIngredientFactsStore
) -> Verdict {
    let meal = FLRestrictions.union(eaters.map(\.restrictions))   // every eater, all layers
    switch store.evaluate(ingredient: substitute.canonicalName, restrictions: meal) {
    case .allowed:
        return Verdict(allowed: true,
                       explanation: "swapping in '\(substitute.canonicalName)' rechecked against every eater: no conflict")
    case .violated(let v):
        return Verdict(allowed: false,
                       explanation: "swapping in '\(substitute.canonicalName)' is not safe: \(v.reason)")
    case .unknown(let u):
        return Verdict(allowed: false,
                       explanation: "composition of '\(substitute.canonicalName)' could not be verified (\(u)) — ask the user before swapping")
    }
}
```

`Fixtures.restriction` (lines 239–245) may keep its `try!` for domain values, but must never wrap the store: the suite obtains the store once via a throwing helper.
