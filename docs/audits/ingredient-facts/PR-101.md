## 2. Fail-open behavior found

1. **Absence from the local maps means allowed.** `restrictionTokensFor` returns `DIRECT_INGREDIENT_RESTRICTIONS.get(id) ?? []` plus `COMPOUND_INGREDIENTS.get(id) ?? []`; `allergenViolations` then short-circuits — line 73: `if (carried.length === 0) return [];`. Anything not hand-listed (~30 entries total) returns zero violations for every eater. Concrete misses: **tamari** (absent; soy sauce is listed but tamari — which carries soy and *maybe* gluten — is not), **cream cheese** (absent ⇒ offered to milk avoiders), **lard** (absent ⇒ offered to vegetarians), **gelatin**, **bacon**, **stock/bouillon cubes**.
2. **No diet handling at all.** The maps encode only allergen tokens. A `vegetarian` eater restriction can only match a token if some ingredient literally carries `"vegetarian"`-matching text — nothing does. `allergenViolations("worcestershire-sauce", [{ restrictions: ["vegetarian"] }])` → Worcestershire carries `["fish","soy"]`; `"vegetarian"` neither contains nor is contained by those tokens → `[]` → **the swap to Worcestershire is offered to a vegetarian**. Likewise lard (`animal fat` isn't a token anywhere) and any meat ingredient absent from the maps.
3. **The suite-D scorer inherits the same maps**, so the "fail-closed scorer" run recorded in `evaluation/suites/lechef/` exercises exactly these ~30 ingredients and can never observe a violation outside them — the suite passes because the checker fails open in its favor.
4. **Substring token matching is brittle both ways.** `token.includes(r) || r.includes(token)` (lines ~85–88): a restriction `"nuts"` matches `"tree nuts"` (good) but also `"coconut"`-style false hits are absent only by luck; a restriction `"so"` would match `"soy"`. No canonical vocabulary on either side.
5. **No unknown state.** Unknown ingredient ⇒ empty token list ⇒ "no violations" — indistinguishable from a verified-safe ingredient. The eaters' free-form restriction strings are never validated, so a misspelled restriction (`"glutan-free"`) silently protects nothing.

## 3. Exact changes needed (file by file)

Goal: replace both maps with the shared dataset; unknown ⇒ "ask the user" (an explicit violation-or-unknown verdict, never `[]`-as-safe); meal restrictions are the union of every eater's restrictions (`FLRestrictions.union`).

### 3.1 New module `backend/gemini-agent/src/lechef/ingredientFacts.ts`

```ts
// Loads data/ingredient-facts (identities.json: key/synonyms/aliases;
// facts.json: components with certainty, allergen facts, diet facts).
export function unionRestrictions(eaters: readonly Eater[]): FLRestrictions; // validated tokens; unrecognized ⇒ throw/flag, never drop
export type FLEvaluation =
  | { kind: "allowed" }
  | { kind: "violated"; reason: string; component: string }
  | { kind: "unknown"; missing: string[] };      // ⇒ ask the user
export function evaluate(ingredient: string, restrictions: FLRestrictions): FLEvaluation;
```

Keep the `Eater` type; validate `restrictions` strings against the `FLAllergen`/`FLDiet` vocabularies at the phone-snapshot boundary.

### 3.2 `backend/gemini-agent/src/lechef/allergens.ts`

Delete `COMPOUND_INGREDIENTS` and `DIRECT_INGREDIENT_RESTRICTIONS`. Re-export thin wrappers over the new module so call sites keep compiling:

```ts
// before
export function allergenViolations(ingredientId, eaters) {
  const carried = restrictionTokensFor(ingredientId).map(normalize);
  if (carried.length === 0) return [];          // FAIL-OPEN
  ...
}

// after
export function allergenViolations(ingredientId: string, eaters: readonly Eater[]): readonly string[] {
  const meal = unionRestrictions(eaters);                       // every eater
  switch (evaluate(ingredientId, meal)) {
    case "violated": return [/* reason naming component, per eater */];
    case "unknown":  return [`unknown-ingredient-facts: ${ingredientId} — ask the user`];
    case "allowed":  return [];
  }
}
```

`recheckSwapAllergens` keeps its both-sides shape (from + to) — that part already matches SPEC 3.1 — but each side now goes through the fail-closed evaluator, so a swap **to** tamari for a gluten-free eater is refused/asked (generic tamari is not gluten-free without a `label` evidence entry).

### 3.3 `backend/gemini-agent/src/lechef/runtime.ts` and `substitutions.ts`

No signature changes — the wrappers above change behavior at the call sites (`runtime.ts:138–141`, `substitutions.ts:150, 201`). Verify the callers distinguish "violated" from "unknown": an unknown verdict must reach the user as a question/confirmation, not as a silent pass and not as a generic refusal.
